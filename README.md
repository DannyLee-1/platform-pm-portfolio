## 대표 프로젝트

### 01. ORBIT · 팀빌딩 매칭 플랫폼

> 아이디어는 있지만 어떤 역할과 팀원이 필요한지 모르는 사람을 위한 팀빌딩 서비스

**2026.06~07 · 부트캠프 3인 팀 프로젝트 · 리더 및 서비스 설계 담당**

이 프로젝트의 목표는 실제 가입자나 매출을 만드는 것이 아니라, 제한된 기간 안에 **제품의 가설을 기획 문서와 MVP 화면으로 구현하는 것**이었습니다. 따라서 운영 성과가 아닌, 문제 정의부터 MVP까지의 논리적 연결과 완성도를 중점으로 봐주시면 감사하겠습니다.

<table width="100%">
<tr><th width="16%" align="left">구분</th><th align="left">내용</th></tr>
<tr><td><strong>담당</strong></td><td>3인 팀 프로젝트 리더 · 문제 정의, 서비스 구조, 핵심 사용자 여정 설계 주도</td></tr>
<tr><td><strong>과제 목표</strong></td><td>막연한 아이디어가 필요한 역할과 팀원 선택, 합류 합의로 이어지는 플랫폼 흐름 설계</td></tr>
<tr><td><strong>문제</strong></td><td>사용자는 필요한 역할을 설명하기 어렵고, 후보의 신뢰도와 합류 조건을 판단하기 어려움</td></tr>
<tr><td><strong>기획 근거</strong></td><td>비전문가 6명의 설문을 근거로, 입력 부담과 신뢰 기준 탐색 · 공개 자료로 공급자 가설과 남은 리스크 점검</td></tr>
<tr><td><strong>핵심 판단</strong></td><td>입력 부담을 낮추고, <strong>추천 근거 · 합류 조건</strong>을 먼저 설계</td></tr>
<tr><td><strong>협업 판단</strong></td><td>팀원이 제안한 서비스명 <strong>ORBIT</strong>을 채택하고, IA·화면정의서는 B2B 직무 경험을 가진 팀원의 조언을 반영해 수정</td></tr>
<tr><td><strong>실행</strong></td><td>PRD → IA → User Flow → Wireframe → 화면정의서 → Prototype → 검증용 MVP 배포</td></tr>
<tr><td><strong>과제 결과</strong></td><td>회원가입부터 프로젝트 구체화 · 후보 선택 · 초대 · 응답 · 합류 합의까지의 핵심 여정 구현 · Vercel 배포</td></tr>
</table>

**핵심 흐름**　`아이디어 한 줄` → `프로젝트 구체화` → `후보 추천` → `초대·응답` → `궁합 확인` → `합류 합의`

> **배운 점:** 가장 중요한 것은 기능을 많이 만드는 것이 아니라, 사용자가 가치를 느끼는 순서와 데이터가 생기는 순서를 맞추는 것

> ORBIT의 과제 성과는 실제 수치가 아니라 2개월 동안 문제 정의와 설계 문서, 프로토타입, MVP를 하나의 흐름으로 완성한 것입니다. 추천 결과와 데모 지표는 화면 검토를 위한 예시입니다.

### 02. 서울시 창의행정 아이디어 사내 공모: 임산부 불빛 배려석 설계

> 시민 의식의 문제가 아니라 **배려가 필요한 순간을 알 수 없게 만든 시스템이 문제**로 재정의했습니다.

<table width="100%">
<tr><th width="16%" align="left">구분</th><th align="left">내용</th></tr>

<tr><td><strong>문제</strong></td><td>상시 공석과 양보 실패가 반복되지만 운영은 개인의 선의와 눈치에 의존</td></tr>
<tr><td><strong>핵심 판단</strong></td><td>좌석을 늘리는 대신 버튼과 불빛으로 <strong>필요한 순간만 보이게</strong> 설계</td></tr>
