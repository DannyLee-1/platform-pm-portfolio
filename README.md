## 대표 프로젝트

### ① ORBIT — 초기 팀 빌딩을 위한 양면 매칭 플랫폼

대규모 채용에는 채용 플랫폼이, 단건 외주에는 프리랜서 마켓이 있습니다. 하지만 아이디어만 있는 초기 창업자는 필요한 역할을 정의하기 어렵고, 합류할 팀원은 프로젝트의 신뢰도와 보상 조건을 판단하기 어렵습니다.

ORBIT은 이 문제를 단순한 ‘사람 추천’이 아니라 **수요자와 공급자 사이의 정보 비대칭과 합류 리스크**로 정의했습니다. 한 줄 아이디어를 역할과 작업으로 구체화하고, 검증된 후보 선택 → 질문과 응답 → 궁합 확인 → 역할·기여·보상 합의까지 연결합니다.

| PM 관점 | 설계 내용 |
|---|---|
| **양면 사용자** | 아이디어 보유자와 합류 희망자의 서로 다른 진입·의사결정 흐름 설계 |
| **신뢰 장치** | 결과물 검증, 아이디어 보호 동의, 답변 후 궁합 공개, 합류 조건 명시 |
| **전환 퍼널** | 아이디어 입력 → 프로젝트 생성 → 후보 선택 → 초대 → 응답 → 합의 |
| **MVP 범위** | 핵심 가설 검증에 필요한 한 역할·한 후보·한 합의 흐름에 집중 |
| **운영 경계** | 외주 적합 사용자 분기, 초대 유효기간, 거절, 재생성 제한, 당사자 책임 고지 |

> **3인 팀 프로젝트**: 문제 정의와 서비스 기획 리드 · 사전 설문부터 PRD, IA, 화면·정책 설계, MVP 배포까지 수행
>
> **구현 상태**: 회원가입·로그인, 프로젝트 생성, 후보 선택, 초대·응답, 궁합 확인, 합류 합의와 단계별 데이터 저장을 구현했습니다. 추천 결과와 데모 지표는 제품 가설을 확인하기 위한 시나리오이며 실제 운영 성과가 아닙니다.
>

### ② 임산부 불빛 배려석 — 행동을 바꾸는 운영·정책 설계

일반 승객은 눈치 때문에 좌석을 비워두고, 임산부는 필요할 때 이용 의사를 알리기 어렵습니다. 이 문제를 개인의 배려 부족이 아니라 **수요 신호가 보이지 않는 시스템 문제**로 재정의했습니다.

버튼과 불빛으로 이용 의사를 전달하는 흐름을 설계하고, 제작 비용·유지관리 주체·악용 방지·민원 가능성까지 함께 검토했습니다. 플랫폼에서도 중요한 **이해관계자 조율, 행동 유도, 운영 정책, 예외 상황 설계** 역량을 보여주는 사례입니다.

> **단독 제안**: 심사 대상 중 유일하게 심사위원 전원 적격 판정 · 서울시 아이디어풀 등재 과제 선정

## 제가 제품을 만드는 방식

1. **현상을 사용자 문제로 바꿉니다.** 인터뷰와 관찰에서 반복되는 불편을 찾고, 해결 가능한 구조로 정의합니다.
2. **양쪽 사용자의 성공 조건을 맞춥니다.** 한쪽의 편의만이 아니라 참여 동기, 신뢰, 이탈 조건과 운영 비용을 함께 봅니다.
3. **가장 작은 검증 단위를 정합니다.** 모든 기능을 만들기보다 핵심 행동이 끝까지 이어지는 범위를 먼저 완성합니다.
4. **개발 가능한 언어로 구체화합니다.** 화면, 상태, 정책, 예외를 연결하고 직접 작동하는 결과물로 확인합니다.
5. **측정 가능한 다음 질문을 남깁니다.** 퍼널의 병목과 가설을 구분하고 다음 실험의 우선순위를 정합니다.
